# MeshCentral ScriptTask

ScriptTask is a fleet-wide script runner for [MeshCentral](https://github.com/Ylianst/MeshCentral). It stores PowerShell, Windows BAT, and Bash scripts centrally, runs them through MeshAgent, schedules recurring work, and keeps the returned output for audit and export.

Version 1.0 modernizes the original plugin for MeshCentral 1.3.0. The execution engine, agent cache, schedules, variables, and existing database remain compatible; the browser workflow is now a standalone **ScriptTask** tab instead of a page nested under one device.

## Requirements

- MeshCentral 1.3.0 or newer
- Plugins enabled in MeshCentral:

```json
"plugins": {
  "enabled": true
}
```

Install with this plugin configuration URL:

```text
https://raw.githubusercontent.com/maxdorx/MeshCentral-ScriptTask/master/config.json
```

Restart MeshCentral after installation or upgrade. ScriptTask then appears in the main navigation bar.

## Main workflow

1. Open the top-level **ScriptTask** tab.
2. Create or upload a `.ps1`, `.bat`, `.bash`, or `.sh` script.
3. Select a script and any number of permitted devices.
4. Choose **Run now** or **Schedule**.
5. Review fleet-wide output under **Results**, filter it, or choose **Export CSV**.

The CSV is generated by the MeshCentral server from stored job history. It is downloaded to the browser; no permanent report file is left on the server.

## Access control

ScriptTask registers separate plugin permissions for viewing, running, editing scripts, and managing variables. MeshCentral administrators can override those permissions for users and user groups.

Every run and schedule is also checked against the user's rights on each requested device. A target is accepted only when it is visible to that user and the user has remote-command rights. An explicit **No Terminal** device right also blocks ScriptTask execution. Hiding the normal Terminal tab alone is therefore not the security boundary—the server-side rights are.

## Storage and execution

- Scripts, variables, schedules, and results are stored in `meshcentral-data/plugin-scripttask.db` when using NeDB, or the `plugin_scripttask` MongoDB collection.
- Records created by version 1.0 include the MeshCentral domain and are isolated by domain. Existing unscoped records remain visible in the default domain.
- Scripts are cached by MeshAgent and checked by content hash before execution.
- Temporary endpoint script/output files are removed after a run.
- Completed job history is retained for 90 days by the existing cleanup process.
- Offline devices retain queued work on the server until the agent reconnects.

## Variables

Variables may be global, script, device-group, or device scoped. More specific values override broader values in this order: global, script, device group, device.

Reference a variable with hashes, for example `#SITE_CODE#`. Missing variables are replaced with `VAR_NOT_FOUND` immediately before execution.

## Safety notes

Scripts execute with the MeshAgent service account's privileges, which are commonly administrative/root. Treat ScriptTask's run permission as privileged access, review scripts before deploying them broadly, and test on a limited device group first.

## Supported databases and platforms

NeDB and MongoDB are supported. BAT runs on Windows; Bash runs on Unix-like endpoints; PowerShell runs on Windows and on Unix-like endpoints where `pwsh` is installed.
